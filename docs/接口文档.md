# API 接口文档

> 前端已实现所有 UI 功能（Demo 模式），后端需实现以下接口。

## 基础信息

- Base URL: `http://localhost:8000`
- Content-Type: `application/json`（除文件上传外）
- 前端开发代理: Vite 会将 `/api` 请求代理到后端

---

## 1. 教材管理 `/api/textbooks`

### 1.1 上传教材

```
POST /api/textbooks/upload
Content-Type: multipart/form-data
```

**请求参数：**
- `files`: 文件数组（支持多文件），格式：PDF, Markdown, TXT, DOCX

**响应：**
```json
{
  "uploaded": [
    {
      "textbook_id": "book_a1b2c3d4",
      "filename": "生理学.pdf",
      "file_type": "pdf",
      "size": 128456789,
      "status": "uploaded"
    }
  ]
}
```

**说明：** 上传后自动触发后台解析任务。

---

### 1.2 获取教材列表

```
GET /api/textbooks
```

**响应：**
```json
[
  {
    "textbook_id": "book_a1b2c3d4",
    "filename": "生理学.pdf",
    "file_type": "pdf",
    "size": 128456789,
    "status": "completed"
  }
]
```

**status 枚举值：** `uploaded` | `parsing` | `completed` | `failed`

---

### 1.3 获取解析状态

```
GET /api/textbooks/{textbook_id}/status
```

**响应：**
```json
{

  "filename": "生理学.pdf",
  "status": "completed",
  "progress": 100,
  "total_pages": 520,
  "total_chars": 385000,
  "chapter_count": 28,
  "error_message": null
}
```

---

### 1.4 获取解析结果

```
GET /api/textbooks/{textbook_id}/parsed
```

**响应：**
```json
{
  "textbook_id": "book_a1b2c3d4",
  "filename": "生理学.pdf",
  "title": "生理学",
  "file_type": "pdf",
  "total_pages": 520,

      "chapter_id": "ch_01",

      "content": "生理学是研究生物体正常生命活动规律的科学...",
      "char_count": 8500
    }

```

---


**响应：**

## 2. 知识图谱 `/api/graph`

### 2.1 获取单本教材图谱数据

```
GET /api/graph/{textbook_id}
```

**响应：**
```json
{
  "nodes": [
    {
      "id": "node_001",
      "name": "动作电位",
      "definition": "细胞受到刺激后膜电位发生的一次快速而可逆的倒转",
      "category": "核心概念",
      "chapter": "第二章 细胞的基本功能",
      "page": 35,
      "textbook": "生理学",
      "textbook_color": "#f59e0b",
      "frequency": 1
    }
  ],
  "edges": [
    {
      "id": "edge_001",
      "source": "node_001",
      "target": "node_002",
      "relation_type": "prerequisite",
      "relation_color": "#f59e0b",
      "description": "理解动作电位需要先掌握静息电位的概念"
    }
  ],
  "stats": {
    "totalNodes": 120,
    "totalEdges": 85,
    "bookCount": 1
  }
}
```

**字段说明：**
- `textbook_color`: 用于前端颜色映射，建议为每本教材分配固定颜色
- `frequency`: 该知识点在多少本教材中出现（跨教材场景下 > 1）
- `relation_type`: `prerequisite` | `parallel` | `contains` | `applies_to`
- `relation_color`: 前端用于边的颜色渲染，建议按关系类型分配

---

### 2.2 获取所有教材的合并图谱

```
GET /api/graph/all
```

**响应格式同 2.1**，包含所有已解析教材的节点和边。

---

### 2.3 触发图谱构建

```
POST /api/graph/{textbook_id}/build
```

**响应：**
```json
{
  "textbook_id": "book_a1b2c3d4",
  "status": "building"
}
```

## 3. 跨教材整合 `/api/integration`

### 3.1 执行整合

```
POST /api/integration/run
```

**响应：**
```json
{
  "status": "completed",
  "decisions": [...]
}
```

---

### 3.2 获取整合决策列表

```
GET /api/integration/decisions
```

**响应：**
```json
[
  {
    "decision_id": "merge_001",
    "action": "merge",
    "affected_nodes": ["book01_node_015", "book03_node_032"],
    "result_node": "merged_node_001",
    "reason": "三本教材都讲解了'炎症'的概念，保留《病理学》的版本因其描述最系统完整",
    "confidence": 0.92,
    "textbook_sources": ["生理学", "病理学", "免疫学"]
  }
]
```

**action 枚举值：** `merge` | `keep` | `remove`

---

### 3.3 修改整合决策

```
PATCH /api/integration/decisions/{decision_id}
Content-Type: application/json

{
  "action": "keep"
}
```

**响应：**
```json
{
  "decision_id": "merge_001",
  "action": "keep",
  "status": "updated"
}
```

**说明：** 教师通过对话修改整合方案时调用此接口。

---

### 3.4 获取整合统计

```
GET /api/integration/stats
```

**响应：**
```json
{
  "originalChars": 5820000,
  "integratedChars": 1650000,
  "compressionRatio": 28.4,
  "mergeCount": 342,
  "keepCount": 267,
  "removeCount": 96,
  "totalDecisions": 705,
  "nodesBefore": 2847,
  "nodesAfter": 1203,
  "edgesBefore": 4562,
  "edgesAfter": 2891
}
```

---

### 3.5 获取压缩比

```
GET /api/integration/compression
```

**响应：**
```json
{
  "original_chars": 5820000,
  "integrated_chars": 1650000,
  "ratio": 28.4,
  "target_ratio": 30.0,
  "meets_target": true

```

## 4. RAG 问答 `/api/rag`

### 4.1 构建向量索引

```
POST /api/rag/index
```

**响应：**
```json
{
  "status": "completed",
  "textbook_count": 7,
  "chunk_count": 2847
}
```

---

### 4.2 查询

```
POST /api/rag/query
Content-Type: application/json

{
  "question": "什么是炎症反应？"
}
```

**响应：**
```json
{
  "answer": "炎症是机体对致炎因子的损伤所发生的防御性反应...",
  "citations": [
    {
      "textbook": "病理学",
      "chapter": "第四章 炎症",
      "page": 78,
      "relevance_score": 0.92
    }
  ],
  "source_chunks": [
    "炎症(inflammation)是具有血管系统的活体组织对各种损伤因子的刺激..."
  ]
}
```

**要求：**
- 回答必须基于检索到的上下文，不使用模型自身知识
- 每个回答必须附带来源引用 `[教材名称, 第X章, 第X页]`
- 如果上下文中找不到答案，回复"当前知识库中未找到相关信息"
- `relevance_score`: 0-1 之间，表示检索相关度

---

### 4.3 查询索引状态

```
GET /api/rag/status
```

**响应：**
```json
{
  "indexed": true,
  "textbook_count": 7,
  "chunk_count": 2847,
  "embedding_model": "BGE-small-zh",
  "vector_store": "FAISS"
}
```

## 5. 多轮对话 `/api/dialogue`

### 5.1 发送消息

```
POST /api/dialogue/message
Content-Type: application/json

{
  "content": "为什么把'炎症'和'炎症反应'合并了？"
}
```

**响应：**
```json
{
  "role": "assistant",
  "content": "合并这两个概念基于以下分析：...",
  "timestamp": "2026-05-10T14:30:00Z"
}
```

**说明：**
- 如果用户请求修改整合方案（如"请保留XX"），后端应：
  1. 调用 `/api/integration/decisions/{id}` 修改决策
  2. 更新知识图谱
  3. 在回复中确认修改并说明影响

---

### 5.2 获取对话历史

```
GET /api/dialogue/history
```

**响应：**
```json
[
  {
    "role": "user",
    "content": "为什么合并了？",
    "timestamp": "2026-05-10T14:28:00Z"
  },
  {
    "role": "assistant",
    "content": "因为...",
    "timestamp": "2026-05-10T14:28:05Z"
  }
]
```

---

### 5.3 清空对话历史

```
DELETE /api/dialogue/history
```

**响应：**
```json
{
  "status": "cleared"
}
```

## 前端切换 Demo 模式

在 `frontend/src/store.js` 中修改 `USE_DEMO` 常量：

```js
const USE_DEMO = true;  // 使用模拟数据，无需后端
const USE_DEMO = false; // 使用真实 API
```

## 技术约束

- RAG 分块：500-800 字/块，50-100 字重叠窗口
- 压缩比：整合后内容 ≤ 原始总字数 30%
- 关系类型至少 3 种：`prerequisite`, `parallel`, `contains`, `applies_to`
- 所有回答必须附带来源引用 `[教材名称, 第X章, 第X页]`
