# 需求分析

## 1 问题分解

本系统的核心问题：**如何将多本教材的知识整合压缩至原内容 30% 以下，同时保证教学效果不打折。**

围绕这一核心问题，我们从以下几个子问题进行分析。

---

## 2 子问题分析

### 2.1 知识点粒度定义

**问题：**教材内容是连续文本，"知识点"没有天然边界——多大算一个知识点？

**分析：**
- 从认知科学角度，知识点应该是**可独立表述的概念**（如"动作电位"、"炎症"、"糖酵解"），而非句子或段落
- 一个知识点可能横跨多个自然段，甚至多个章节（"酶"在生物化学各章反复出现）
- 知识点的粒度直接影响去重效果：粒度太粗（整章）去重效果差，粒度太细（单词）则碎片化

**结论：**以**章节内 LLM 提取的结构化概念节点**为基本单位。每个节点包含：名称、定义、类别、所属章节、页码。这是承上启下的最小粒度。

---

### 2.2 重复判定标准

**问题：**如何判断两个来自不同教材的知识点是"同一个"？

**分析：**
- 词面相同 → 显然重复（如两本教材都叫"动作电位"）
- 词面不同但语义相同 → 需要语义对齐（如"炎症"和"炎症反应"，"白细胞"和"leukocyte"）
- 词面不同且语义不同但名称相似 → 易误判（如"抗体"和"抗毒素"）

**判定方法（二选一或结合）：**

| 方法 | 优点 | 缺点 |
|------|------|------|
| 文本嵌入（Embedding）相似度 | 快速、可规模化 | 阈值敏感，中文Embedding模型质量参差不齐 |
| LLM 判断等价性 | 准确率高，可解释 | 贵且慢，需 API 费用 |

**本系统采用策略：**Embedding 初筛 + LLM 仲裁。
1. 用 Embedding 计算候选对的余弦相似度
2. 阈值 > 0.85 → 自动合并
3. 阈值 0.70~0.85 → LLM 判断是否等价
4. 阈值 < 0.70 → 保留为不同知识点

**为什么这样设计：**纯 Embedding 会有误判（如"抗体"vs"抗原"可能相似度高但不是同一概念），纯 LLM 太贵。两者结合兼顾效率和准确率。

---

### 2.3 教学连贯性保障

**问题：**去重后如何保证教学逻辑链路不断裂？

**分析：**
- 知识点之间存在 **prerequisite（前置依赖）**关系（如"静息电位"是"动作电位"的前置）
- 如果简单按字数压缩，可能删除"前置知识点"，导致学习路径断裂
- 跨教材去重时，同一概念可能多本教材都教，但删除哪本教材的版本需要考虑：
  - 该教材的整体定位（基础课 vs 专业课）
  - 版本的描述质量（系统性、完整性）
  - 该知识点在该教材中的上下文是否不可替代

**保障机制：**
1. 知识图谱中保留 **prerequisite** 关系链
2. 整合压缩后，验证每条 prerequisite 链的完整性（两端节点都存在）
3. 若某链断裂，通过 RAG 向量检索补偿缺失的上下文

---

### 2.4 压缩比计算方式

**问题：**"压缩至 30%" 怎么计算？

**公式：**

```
压缩比 = 整合后总字数 / 原始总字数 × 100%
```

**"整合后总字数"包括：**
- 合并节点的整合版内容（取最长版本的 50% + 其他版本的 20% 作为补充）
- 保留节点的完整内容
- 删除节点不计入

**"原始总字数"包括：**
- 所有教材正文总字数（不含目录、索引、图表说明）

**为什么这样计算：**这是 statement.md 中"不超过原始体量 30%"的本意——即最终呈现给学生的整合版教材体量。

**实际做法：**先合并节点，再统计合并后的内容总字数，与原始总字数对比。实时显示压缩进度。

---

### 2.5 RAG 分块策略选择依据

**问题：**RAG 系统的文档分块为什么选择 500-800 字/块，50-100 字重叠？

**分析：**

| 策略 | 优点 | 缺点 |
|------|------|------|
| 细粒度（100-200 字） | 精确匹配关键词 | 上下文碎片化，跨块推理困难 |
| 中等（500-800 字） | 平衡精度与上下文 | 可能截断知识点 |
| 粗粒度（2000+ 字） | 强上下文连贯性 | 检索粒度粗，精确度下降 |

**选择 500-800 字的理由：**
1. LLM 单次处理的上下文窗口通常在 4K-128K tokens，500-800 字（约 250-400 tokens）可确保单个 chunk 不超过上下文窗口的 10%
2. 医学教材中，一个核心概念（如"炎症"）的定义和基本描述通常在 500-800 字之间
3. embedding 模型对中文的最佳长度通常在 256-512 tokens，超长文本会稀释语义焦点

**重叠 50-100 字的理由：**
- 知识点可能在块边界处被截断（如第一章末尾的"细胞"概念在第二章继续）
- 50-100 字的滑动窗口（sliding window）确保跨块知识点至少被完整检索一次
- 重叠过少（<50字）效果不明显，重叠过多（>200字）浪费索引容量

**索引构建流程：**
```
文本 → 500-800字分块（50字重叠）→ BGE-small-zh embedding → FAISS 向量存储
```

## 6 技术选型

### 6.1 PDF 解析：PyMuPDF (fitz)

- **优点：**纯 Python实现，速度快，内存可控；支持逐页解析，不会 OOM
- **章节识别：**正则匹配"第X章" + 字体大小判断 + TOC 目录页提取，三重保障
- **页眉页脚过滤：**通过 Y 坐标过滤（顶部 5% 和底部 5% 排除）

### 6.2 向量嵌入：sentence-transformers (BGE-small-zh)

- 支持多语言（特别是中文），参数少速度快
- 纯本地运行，无需 API 费用

### 6.3 向量存储：FAISS

- Facebook 开源，支持亿级向量高速检索
- CPU 友好，适合黑客松场景的快速部署

### 6.4 LLM：DeepSeek API

- 性价比高，中文能力强
- 用于知识点提取（逐章节调用）和跨教材语义对齐判断

---

## 7 关键约束总结

| 约束 | 具体要求 |
|------|---------|
| 压缩比 | ≤ 30%（整合后/原始总字数） |
| RAG 分块 | 500-800 字/块，50-100 字重叠 |
| 关系类型 | 至少 3 种：prerequisite, parallel, contains, applies_to |
| 引用格式 | `[教材名称, 第X章, 第X页]` |
| 知识图谱交互 | 点击节点查看详情，缩放拖拽，频次可视化 |
